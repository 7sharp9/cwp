### Why this task, in this shape

The standing review's "Two correctness defects" section, defect 1 (passable
zero-cost terrain breaks the A* optimality claim). Verified against source
before drafting:

- `src/CommandoWar.Sim/Scenario.fs` terrain-layer validation only reports
  `NegativeMoveCost` for `tc.MoveCost < 0`. A passable cell with
  `MoveCost = 0` passes `Scenario.validate`.
- `src/CommandoWar.Sim/Pathfinding.fs` heuristic is
  `(abs dx + abs dy) * Terrain.BaseMoveCost`, and the module comment states it
  is "Admissible for cardinal moves whose minimum step cost is
  `Terrain.BaseMoveCost` (authored passable cells respect this)". That
  precondition is false. `findWithin` does not reopen closed nodes
  (`if not closed.[ni]`), so it needs a *consistent* heuristic for
  optimality, which the Manhattan heuristic is only when every step costs
  `>= BaseMoveCost`.
- `tests/CommandoWar.Sim.Tests/DeterminismPropertyTests.fs` property 3
  recomputes the *returned* path's own cost (`recomputedCost`) and checks
  adjacency/passability/endpoints; it never compares against an independent
  shortest path, and its `cellClassGen` only emits passable costs 1, 2, 3.
- `src/CommandoWar.Sim/Terrain.fs`: `BlockedCost = System.Int32.MaxValue`,
  `moveCost` returns `t.MoveCost.[i]` for a passable cell with no upper bound,
  so a passable cell authored at `Int32.MaxValue` collides with the sentinel,
  and `Pathfinding`'s `g.[ci] + Terrain.moveCost terrain nb` is unchecked
  `int` (defect 1's second half, review point 5 of the required correction).
- `src/CommandoWar.Sim/Simulation.fs` `wouldComplete`:
  `startProgress + Terrain.BaseMoveCost >= Terrain.moveCost terrain next`
  degenerates to always-true at a 0 threshold — a further reason the review
  prefers the minimum-cost rule over a zeroed heuristic.

### Design choices recorded in the task file

- Minimum-cost model (`MoveCost >= BaseMoveCost`), not a zeroed heuristic:
  keeps A* guidance (R-010) and fixes the `Progress`-threshold degeneracy;
  makes the existing heuristic provably consistent, which is what the
  no-reopening A* needs.
- New `Terrain.MaxMoveCost` literal (recommended `1000`) as the passable
  ceiling: fixes the `BlockedCost` sentinel collision that widening arithmetic
  alone would not, and bounds accumulation inside `int32`. The implementing
  agent may pick another value against a stated non-overflow inequality.
- One `ScenarioError` case `MoveCostOutOfRange of cell * cost * min * max`;
  `NegativeMoveCost` kept for `< 0` or folded in, implementer's call, as long
  as every bad value yields one actionable error.
- No A* algorithm change — only the `## Bounded work` non-overflow comment.
- No committed scenario is expected to violate the rule (authored costs are
  1/2/3 today); the implementing agent must grep and **stop-and-report** if
  one does, rather than re-author content and re-pin hashes.
