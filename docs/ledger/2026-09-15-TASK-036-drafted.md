### Central decisions confirmed with Dave via `AskUserQuestion` before drafting

1. **Commit `.cwreplay` (`ReplaySerialisation`), not `.cwlog`, for migrated
   entries** (Decision A in the task file) — the frozen `.cwlog` v1 grammar
   cannot express multi-recipient commands, `Urgency`, `RiskTolerance`, or a
   distinct issue tick; `.cwreplay` already can (B-045). This is what the
   original B-049 proposal anticipated ("when B-045 picks a format, the
   builder emits it").
2. **Migrate all eleven existing `rawScenario`-based corpus entries, not
   just future ones** (Decision B) — confirmed over "build the builder,
   apply only to new entries," since leaving the eleven in place alongside
   an unused parallel builder would fix nothing.

Two further decisions were made directly (not put to Dave, since they
follow from repository conventions already established) and recorded in
the task file:

3. **The builder's authored value is the sole runtime source of truth;
   `.cwreplay` is a generated, checked artefact, not read back** (Decision
   C) — eliminates the drift risk categorically rather than moving it,
   following the `<name>.md` regenerate-and-diff precedent already in
   `Corpus.fs`.
4. **No retrofit of `SimulationTests.fs`'s ~280 existing facts** (Decision
   D) — that file does not use `rawScenario`/`Corpus` today (it builds
   `WorldState` directly via `Setup.sixAgentWorld`); rewriting it is
   unrelated-refactor scope under `AGENTS.md` for a stated "S–M" item. The
   builder is shaped so a *future* `SimulationTests` fact can reuse it; this
   task does not force that reuse retroactively.
5. **No new geometry-solving helper** (Decision E) — `wall`/`opaqueWall`/
   `costly` migrate as-is; the B-049 note's "geometry by hand" cost is
   explicitly out of scope for this task.
