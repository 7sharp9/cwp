### Why this task, in this shape

The standing review's "Two correctness defects" section, defect 2 (runtime cell
occupancy is not protected). Verified against source before drafting:

- `src/CommandoWar.Sim/Simulation.fs` `navigationAndMovement`, Pass 3, the
  `Advancing(r, next, dest, startProgress)` arm: `yieldedTo.TryFind idx` with a
  `None` result assigns `{ a with Position = next; ... }` with **no test on
  whether another agent's `Position` already equals `next`**. The only
  cross-agent check anywhere in the phase is Pass 2 `yieldedTo`, which groups
  `Advancing` intents `by (fun (_, _, _, next) -> next)` — i.e. it only sees
  agents that *both* would complete an edge into the *same* cell this tick. An
  agent whose next cell is held by an idle / blocked / arrived / mid-edge /
  contest-loser agent has no rival in that grouping and moves unconditionally.
- `src/CommandoWar.Sim/Pathfinding.fs` (via the phase's `Pathfinding.findWithin`
  call) plans over `Terrain` passability and entry cost only; `Pathfinding`
  never receives agent positions, so a route legitimately passes through an
  occupied cell.
- `docs/ledger/2026-09-04-TASK-017-cell-reservation.md`, "Deviations":
  explicitly records that reservation "does not resolve an agent moving onto a
  cell held by a stationary agent" and "does not defend against a rotation
  deadlock", and flags both for "whoever designs B-011c or a later multi-agent
  scenario". B-011c (TASK-018) was narrowed to sub-cell progress and B-011d to
  formation slots; neither picked this up.
- `tests/CommandoWar.Sim.Tests/DeterminismPropertyTests.fs` property 2 asserts
  only `Terrain.passable state.Terrain a.Position` for every agent every tick —
  never that two agents hold distinct cells. Property 1 (self-replay
  determinism) would not catch a shared cell either: both runs share it
  identically.
- `src/CommandoWar.Sim/Domain.fs` / `Simulation.fs` `World.build`: enforces
  empty-grid, duplicate-id, and in-bounds; **not** cell-sharing.
  `Scenario.validate` does reject a cell-sharing deployment (`docs/04` section
  21), and `Setup.sixAgentWorld` / `World.create` / the property generator all
  place agents on distinct cells, so the pre-tick uniqueness invariant holds by
  construction on every path today — it is only unprotected *after* a movement
  tick.
- `src/CommandoWar.Headless/Corpus.fs`: `spike-fixture` (1 mover among 5
  stationary, A* route never crosses column `x = 0`), `wall-detour` /
  `blocked-goal` / `slow-terrain` (single agent), `converging-routes` (2
  agents, shared-target contest with agent 0 always in motion, so agent 1 only
  enters `(3,3)` after agent 0 vacates it). None exercises a mover entering a
  cell held by a stationary agent, so no committed hash is expected to move.
- `docs/04_SIMULATION_SPEC.md` section 20 lists "one live agent has one
  authoritative position" but nothing enforces the pairwise "distinct live
  agents occupy distinct cells".

### Design choices recorded in the task file

- **Extend Pass 2, not a pre-pass.** A new stage 2b (vacation-chain
  resolution) runs after TASK-017's rival arbitration (stage 2a, unchanged) and
  before Pass 3 apply, producing an `obstructedBy` map consumed by one new
  Pass 3 arm. Pass 1 and the three-pass shape are untouched; the rival rule
  (priority by remaining route steps, ties by agent id) is untouched.
- **Vacation-chain rule as an additive fixpoint.** Seed with candidate movers
  whose target cell is empty of every agent; each round add a candidate whose
  target cell's occupant is already known to move; the fixpoint is the mover
  set, everything else is obstructed. Monotone, ≤ n rounds, order-independent
  within a round (consults only the previous round). A memoised DFS with cycle
  detection is an allowed equivalent.
- **Swaps and rotation cycles are blocked, and this falls out of the fixpoint
  with no special case** — a pure n-cycle never seeds a first mover. The task
  records deliberately *not* adding simultaneous rotation (needs an atomic-swap
  primitive and a tactical reason, neither exists).
- **New `MovementObstructed of agent * at * blocked * occupant` event**,
  distinct from `MovementBlocked` (no path, destination cleared) and
  `MovementYielded` (lost a rival contest to a mover). Destination and route
  unchanged; the agent retries next tick.
- **Persistent obstruction is not resolved here.** A mover permanently blocked
  by an agent that never moves emits `MovementObstructed` every tick forever.
  Routing around a live agent is the forbidden cooperative pathfinder; a
  give-up timer is an arbitrary constant. Flagged for B-015 / B-017
  (perception / appraisal — the stalled agent should notice and re-appraise).
- **No `Canonical.FormatVersion` bump, no new state, no hash re-pin.**
  `Canonical.encode` is untouched; no `AgentState` / `WorldState` field is
  added; the resolution is a same-tick pure function of pre-tick canonical
  positions plus this tick's intents (the identical argument that kept
  reservation non-canonical in TASK-017). The implementing agent must run
  `-- corpus` / `-- fixture` before and after and **stop-and-report** if any of
  the five existing entries' or the fixture's hashes move.
- **Optional `World.build` cell-sharing guard.** The implementer *may* add a
  `WorldError.AgentsShareCell` guard to complete the invariant at construction,
  with a one-line justification, if it stays contained; otherwise leave it
  (the scenario validator already covers authored content).
- **Diagnostics:** new `Overlay.Obstructed of cell * occupant` derived in
  `frameOf` from `MovementObstructed` events, an `eventMarker` arm, four
  `DiagnosticRender.fs` branches (expect four `FS0025` errors first), a golden
  and a hand-built overlay unit test — the TASK-017 `Reserved` precedent.

### Deviations and unresolved issues

- The task is `ready` with `Dependencies: none`. It does not depend on TASK-020
  or TASK-021; all three can run in any order. The review sequences this one
  before B-015 (perception) and B-019 (combat).
- Persistent obstruction (a mover permanently blocked by a never-moving agent)
  is left unresolved by design and pushed to B-015 / B-017. No new backlog item
  was created for it — it is a property of those systems' scope, not standalone
  work — but whoever drafts B-015 / B-017 should confirm the stalled agent
  re-appraises rather than emitting `MovementObstructed` in silence forever.
- The "converging on a cell held by a stationary agent" case yields
  `MovementYielded` for the rival loser and `MovementObstructed` for the rival
  winner in the same tick under the layered rule. The task permits an optional
  static-occupant check before rival arbitration so all converging claimants
  get `MovementObstructed` instead; left to the implementer as long as no other
  case's events change.
- Whether to add the `World.build` cell-sharing guard is left to the
  implementer. If added, `WorldError` consumers and one test move with it.
- The `Obstructed` overlay could be folded into the existing `Reserved` case;
  the task recommends a separate case (`Reserved` carries `untilTick` and a
  contest `winner`, neither of which fits a stationary blocker) but does not
  forbid folding.
