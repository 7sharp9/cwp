### Why

B-023's four dependencies (B-018, B-020, B-021, B-022) are all `done` as of
TASK-037, so this row is selectable per `docs/11_BACKLOG.md` section 7 ("all
dependencies are `done`"). Steps 1-3 and 5-6 of `docs/07` section 8's
canonical refusal sequence already exist piecemeal (`exposed-approach`,

### Central decision (confirmed with Dave via `AskUserQuestion` before drafting)

`docs/07` section 8 step 8 says the soldier "accepts **or adapts** it
consistently." No `Adapted` `OrderDisposition` case exists anywhere in the
codebase — `Appraisal.fs`'s own doc comment: "Stage 5 (safer adaptation) is
deferred (B-018): no `Adapted` outcome, no route recomputation." Building
stage-5 `Adapted` is a separate, materially larger, unscoped feature.

Dave chose: prove the accepts-branch only (the reissued order is `Accepted`
consistently — once via the automatic reappraisal trigger, once more via an
explicit player reissue) and close B-023 `done` on that reduced
interpretation. The `Adapted`/stage-5 half is recorded as a new, not-yet-filed
follow-up, not silently dropped.

### Deviation from the drafted task file

The drafted task file's "Allowed scope" included a new golden diagnostic
pair as though required. On inspection, `AGENTS.md`'s diagnostics rule only
*mandates* a new golden when a task "adds or changes authoritative spatial
or tactical state" — this task adds none (no new `Overlay` case; the
identical situation TASK-037 was in, which shipped `suppress-relieves-
exposure` with no dedicated golden at all, relying on `SimulationTests`
facts and corpus/hash pinning alone). The golden pair was added anyway,
since B-023 is explicitly G3's headline evidence item and the two other
headline entries (`exposed-approach`, `reissued-order`) both have one — not
a correctness requirement, a legibility choice.
